# Cat-ch 🐾

**捕捉猫咪，也收藏心动。** Cat-ch 是一个分享小猫照片的安卓应用：看看别人遇见的小猫，也把你拍到的可爱瞬间分享出来。

## 下载安装

1. 打开 [下载页面](https://github.com/adrian147258/Cat-ch/releases/tag/v0.9.1-beta)。
2. 在 **Assets** 中下载 `Cat-ch-0.9.1.apk`。
3. 在 Android 手机中打开安装包，按系统提示安装。需要 Android 8.0 或更新版本。

这是测试版，尚未完成所有真机测试。如果手机提示安装来源权限，请根据设备的系统提示选择是否允许安装。

0.8 更换了应用签名，已安装 0.7 或更早版本的用户需要卸载旧版后再安装；卸载会清除旧版保存在手机本地的数据。已安装 0.8.0、0.8.1 或 0.9.0 的用户可以直接覆盖安装 0.9.1。

## 怎么使用

1. 打开 App，用邮箱注册并完成验证码验证；之后可使用邮箱和密码或邮箱验证码登录。
2. 在 **广场** 浏览其他人发布的小猫，喜欢的内容可以点赞或收藏。
3. 点击底部 **＋** 选择图片和小猫种类，写下文字并发布；发布后，其他使用者可以看到。
4. 在 **我的** 查看发布、点赞和收藏；可以编辑个性签名，点 **＋** 更换猫猫窝封面。封面按原比例完整显示。

在帖子详情点击照片可全屏查看，支持双指或双击缩放、放大后拖动、复原和关闭。多图帖子可在原比例下左右滑动切换，也可使用上一张／下一张按钮。广场的「偶遇一只猫」会从当前已加载的帖子中随机打开一篇；有多篇可选时避免连续选中同一篇，不额外请求后台。

在广场或发现页长按其他人的帖子，选择「不感兴趣」即可隐藏。隐藏记录按本机账号保存，广场、发现和随机看猫会过滤这些帖子，不删除原帖或改变点赞、收藏；可在「设置 → 恢复不感兴趣的帖子」恢复全部。设置中的「外观」支持跟随系统（默认）、浅色和深色，选择会保存在本机。

发布页会按账号在本机保存文字、种类和已选照片，重新打开可继续编辑；卸载应用会清除草稿。可调整照片顺序、设置第一张为封面或移除照片。原图支持最大 30 MB，自动缩小、校正照片方向并压缩后上传。上传过程中显示进度，上传结束后等待服务器确认；失败保留草稿。如果连接中断导致发布结果无法确认，请先查看「我的发布」，确认未发布后再重试。

广场已合并为单一列表，保留搜索和下拉刷新。列表按可见区域复用卡片，图片按显示尺寸解码，并使用最多约 120 MB 的本机磁盘缓存；离屏图片请求会取消。启动先显示已保存的内容并刷新广场，检查更新在独立队列执行；刷新失败时可点击提示重试。

发帖、登录与浏览社区需要联网和可用的后台服务。重新保存后的封面和个性签名可同步至公开主页；成就等级制度尚未加入。

## 开发与实现

客户端采用 **Kotlin + Jetpack Compose + Material 3** 开发（保留原 Java 上传与草稿核心模块），登录和社区数据由后端服务提供。本仓库包含 Android 客户端及 backend 目录中的后端源码。构建时需要自行配置服务地址，下载的测试版安装包已配置现有服务。

使用 Android Studio 打开项目（或在命令行运行 `./gradlew :app:assembleDebug`），安装 JDK 17 和 Android SDK 35。构建前在未提交的 `local.properties` 中配置自己的服务地址：

```properties
catch.apiBaseUrl=https://your-api.example.com
```

调试签名由开发环境生成。正式版签名通过项目根目录下未提交的 `signing.properties` 配置，支持 `storeFile`、`storeType`、`storePassword`、`keyAlias` 和 `keyPassword`。不要上传签名文件、密码、API 密钥、会话令牌或生产配置。

## 后端配置

配置 DB (D1)、PICTURES (R2)、AUTH_BASE_URL、BREVO_SENDER_EMAIL，以及私密 BETTER_AUTH_SECRET、BREVO_API_KEY。现有数据库新增功能需运行 backend/cards-migration.sql 和 backend/comments-migration.sql；不要重置已有数据。后端鉴权使用 better-auth，构建时需按目标运行环境配置 Node 兼容。

为已有数据库添加小猫种类时，在部署新版后端前运行一次 `backend/breeds-migration.sql`；新数据库使用更新后的 `schema.sql`，不需要再运行该迁移。已有帖子会保持未分类，旧版客户端发布的帖子也不会被猜测分类。

个人主页需要在已有数据库中运行 `backend/profiles-migration.sql`。公开主页只提供签名、封面和本人发布的作品；点赞与收藏不会作为他人的主页资料返回。原本仅保存在设备上的签名和封面不会自动公开，需要用户重新保存或选择后才会同步。

### 后端部署说明

- 多图版本必须先执行 `backend/post-images-migration.sql`，再部署 Worker，最后更新 App。迁移只新增图片表、可重复运行，旧单图帖子仍可读取。未迁移就部署代码会导致广场、主页及删除接口查询失败。
- 一篇帖子最多 9 张，每张上传文件上限为 5,000,000 字节（5 MB）；客户端允许最多 30,000,000 字节的原图，采样、校正方向和压缩后再检查上传大小。多图共用一次发帖配额、一份评论和点赞总数，失败不会发布部分图片。以前被拆成多篇的帖子不会自动合并。
- 软件公告使用 `backend/announcement-migration.sql` 创建的数据表。登录后新公告会展示一次，可在「我的」中回看；发布公告位于「设置 → 管理员发布公告」，需要登录及 Worker 机密 `ANNOUNCEMENT_ADMIN_KEY`。口令不得提交到源码或安装包。
- 点赞数公开，API 不提供点赞者名单。主页作品中的 `liked`/`saved` 仅代表当前请求者对该作品的状态，不是主页所有者的点赞或收藏列表。
- 忘记密码邮件使用 QQ 邮箱 SMTP，需要 Worker Secret `QQ_SMTP_USER`（完整 QQ 邮箱地址）和 `QQ_SMTP_PASSWORD`（SMTP 授权码，不是 QQ 登录密码）。注册与登录验证码继续走 Brevo。重置发信失败不会回退占用 Brevo 额度。重置成功会使旧登录会话失效。构建 Worker 时应保留 `cloudflare:sockets` 作为外部模块。
- 执行 `cd backend` 后运行 `npm test` 检查模拟数据库和邮件传输；测试不会发送真实邮件。
